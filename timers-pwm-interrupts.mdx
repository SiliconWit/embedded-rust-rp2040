A variable shared between the main loop and an interrupt handler (ISR, interrupt service routine) is the source of the faults that appear once a week and never on the bench. In C you mark it `volatile` and hope the interrupt never arrives at the wrong moment. Rust does not compile a global that both sides can change freely: you must protect it with a critical section, a Mutex, or an atomic type. In this lesson you drive a servo with PWM, read a potentiometer with the ADC, and write a timer interrupt that plays a tone on a buzzer, with the shared data protected in a way the compiler can check. #RP2040 #PWM #Interrupts

## RP2040 PWM Architecture

<InArticleAd />

A hobby servo reads its target angle from the width of a pulse: 0.5 ms means 0 degrees and 2.5 ms means 180 degrees, repeated every 20 ms. A pulse that is 0.1 ms wrong moves the arm by 9 degrees, so the timing cannot depend on what the program is doing. The PWM hardware makes the pulse with a counter and needs no CPU time.

The RP2040 has 8 PWM blocks, called slices. In each, a divider slows the system clock and a 16-bit counter counts from 0 to a top value (wrap), then starts again. Outputs A and B are each high while the counter is below their own compare value, so they share one frequency but can have different pulse widths.

```text
  125 MHz      ┌─────────┐   ┌───────────┐
  system ─────►│ Divider │──►│ Counter   │
  clock        └─────────┘   │ 0 .. wrap │
                             └─────┬─────┘
                    ┌──────────────┴─────┐
                    ▼                    ▼
             ┌────────────┐       ┌────────────┐
             │ Compare A  │       │ Compare B  │
             └─────┬──────┘       └─────┬──────┘
                   ▼                    ▼
               pin A (GP0)          pin B (GP1)
```

### PWM Slice Mapping

Each GPIO pin belongs to one slice and one channel. The slice is the pin number divided by 2, with the fraction dropped, and it starts again from 0 at GP16. Even pins are channel A and odd pins are channel B. So GP0 is slice 0 channel A, GP1 is slice 0 B, GP15 is slice 7 B, and GP16 is slice 0 A again.

In this project the servo on GP0 uses slice 0 channel A. GP18 could use slice 1 channel A, but here the buzzer pin is a plain GPIO output that a timer interrupt switches.

### PWM Frequency Calculation

Two settings fix the frequency. The divider sets how fast the counter counts, and the wrap value sets how far it counts before it starts again. With the system clock $f_{sys}$ = 125 MHz, the counter frequency is:

$$
f_{counter} = \frac{f_{sys}}{divider}
$$

The counter takes $wrap + 1$ counts for one period (it counts from 0), so the output frequency is:

$$
f_{pwm} = \frac{f_{counter}}{wrap + 1}
$$

A servo needs 50 Hz, a period of 20 ms. A divider of 125 gives a counter frequency of 125 MHz / 125 = 1 MHz, so one count is 1 microsecond. A period of 20 ms is then 20,000 counts, and the wrap value is 19999:

$$
f_{pwm} = \frac{1{,}000{,}000 \text{ Hz}}{19999 + 1} = 50 \text{ Hz}
$$

One count is 1 microsecond, so the compare value is the pulse width in microseconds:

| Servo Angle | Pulse Width | Compare Value (at 1 MHz counter) |
|-------------|-------------|----------------------------------|
| 0 degrees | 0.5 ms | 500 |
| 90 degrees | 1.5 ms | 1500 |
| 180 degrees | 2.5 ms | 2500 |

### Setting the Duty Cycle for a Specific Angle

```rust
/// Map an angle (0 to 180) to a PWM duty cycle value.
/// Servo expects 0.5 ms (500) to 2.5 ms (2500) pulse within a 20 ms period.
fn angle_to_duty(angle: u16) -> u16 {
    let angle = if angle > 180 { 180 } else { angle };
    // Linear interpolation: 0 deg -> 500, 180 deg -> 2500
    500 + ((angle as u32 * 2000) / 180) as u16
}
```

## ADC: Reading the Potentiometer

<InArticleAd />

The ADC of the RP2040 turns a voltage into a 12-bit number: 0 for 0 V up to 4095 for 3.3 V. It has 5 inputs: ADC0 to ADC3 on GP26 to GP29, and an internal temperature sensor. It takes up to 500,000 samples per second.

```rust
use rp2040_hal::adc::Adc;

/// Read ADC channel 0 (GP26) and return a 12-bit value (0 to 4095).
fn read_pot(adc: &mut Adc, adc_pin: &mut hal::adc::AdcPin<
    hal::gpio::Pin<hal::gpio::bank0::Gpio26, hal::gpio::FunctionNull, hal::gpio::PullDown>,
>) -> u16 {
    adc.read(adc_pin).unwrap()
}
```

### Mapping ADC to Servo Angle

Scale the reading to 0 through 180 degrees. A reading of 2048 gives 2048 × 180 / 4095 = 90 degrees:

```rust
/// Map a 12-bit ADC value (0 to 4095) to a servo angle (0 to 180).
fn adc_to_angle(adc_value: u16) -> u16 {
    ((adc_value as u32 * 180) / 4095) as u16
}
```

## Interrupts in Rust

<InArticleAd />

The buzzer tone comes from a timer interrupt: each time it fires, the handler switches the pin and sets the next alarm. The main loop decides the pitch, so the two must share a variable.

### Why Rust Interrupts Are Different

In C, an interrupt handler reads and writes global variables freely:

```c
// C: common ISR pattern
volatile uint32_t tone_half_period_us = 0;
volatile bool buzzer_state = false;

void TIMER_IRQ_0_Handler(void) {
    timer_hw->intr = 1;  // clear interrupt
    buzzer_state = !buzzer_state;
    gpio_put(18, buzzer_state);
    // Schedule next interrupt
    timer_hw->alarm[0] = timer_hw->timerawl + tone_half_period_us;
}
```

This works, but the compiler checks nothing:
- The main loop may write `tone_half_period_us` while the ISR reads it. One 32-bit write happens to be a single step on a Cortex-M, but the compiler does not know or check that.
- When someone adds a second variable that must change together with the first, the ISR can fire between the two writes.

Rust does not compile this pattern. A global variable that can change must be protected.

### The Rust ISR Pattern

An interrupt handler takes no arguments, so everything it uses must be a global (`static`). Each shared item is wrapped three times, and each wrapper answers one question:

- `Mutex`: who may touch it now? Only code inside a critical section (interrupts off), which holds the token `cs`.
- `RefCell`: how can a global declared without `mut` change? It allows the change and checks the rule of one writer at run time.
- `Option`: what is in the global before `main()` has set the peripheral up? `None`. In C the handler would use a peripheral that is not ready, or a NULL pointer. Here it must test for `Some` first, with `if let Some(...)`.

```rust
use core::cell::RefCell;
use critical_section::Mutex;
use rp2040_hal::pac;
use rp2040_hal::pac::interrupt;

// Shared state: the timer alarm peripheral and buzzer configuration
// Wrapped in Mutex<RefCell<Option<T>>> because:
// - Mutex: requires critical section token for access (interrupt-safe)
// - RefCell: provides interior mutability (borrow checking at runtime)
// - Option: starts as None, set to Some() after peripheral init
static ALARM0: Mutex<RefCell<Option<pac::TIMER>>> = Mutex::new(RefCell::new(None));
static BUZZER_HALF_PERIOD: Mutex<RefCell<u32>> = Mutex::new(RefCell::new(0));
static BUZZER_PIN: Mutex<RefCell<Option<hal::gpio::Pin<
    hal::gpio::bank0::Gpio18,
    hal::gpio::FunctionSio<hal::gpio::SioOutput>,
    hal::gpio::PullDown,
>>>> = Mutex::new(RefCell::new(None));

#[interrupt]
fn TIMER_IRQ_0() {
    critical_section::with(|cs| {
        // Access shared peripherals inside the critical section
        if let Some(ref timer) = *ALARM0.borrow_ref(cs) {
            // Clear the interrupt
            timer.intr().write(|w| w.alarm_0().clear_bit_by_one());

            // Read the desired half-period
            let half_period = *BUZZER_HALF_PERIOD.borrow_ref(cs);

            if half_period > 0 {
                // Toggle the buzzer pin
                if let Some(ref mut pin) = *BUZZER_PIN.borrow_ref_mut(cs) {
                    // Toggle: read the output state, then write the opposite
                    let current = pin.is_set_high().unwrap_or(false);
                    if current {
                        pin.set_low().unwrap();
                    } else {
                        pin.set_high().unwrap();
                    }
                }
            }

            // Schedule the next alarm. An alarm fires only once, so it
            // must always be re-armed. While the buzzer is off, check
            // again every 10 ms so that a new half-period is picked up.
            let interval = if half_period > 0 { half_period } else { 10_000 };
            let next = timer.timerawl().read().bits().wrapping_add(interval);
            timer.alarm0().write(|w| unsafe { w.bits(next) });
        }
    });
}
```

### Key Differences from C

<TabItem label="C ISR Pattern">
```c
// Global mutable state: no synchronization
volatile uint32_t half_period = 0;
volatile bool pin_state = false;

void TIMER_IRQ_0_Handler(void) {
    // Clear interrupt flag
    timer_hw->intr = 1;

    // Toggle pin
    pin_state = !pin_state;
    gpio_put(18, pin_state);

    // Schedule next
    timer_hw->alarm[0] =
        timer_hw->timerawl + half_period;
}

int main(void) {
    // Set half_period from main loop
    half_period = 500;  // No synchronization
    // What if ISR fires right now and reads
    // a partially-updated value? On 32-bit
    // Cortex-M this is actually atomic for
    // 32-bit writes, but the compiler does
    // not verify this.
}
```

<TabItem label="Rust ISR Pattern">
```rust
static HALF_PERIOD: Mutex<RefCell<u32>> =
    Mutex::new(RefCell::new(0));

#[interrupt]
fn TIMER_IRQ_0() {
    critical_section::with(|cs| {
        let hp = *HALF_PERIOD.borrow_ref(cs);
        // Access is inside a critical section:
        // interrupts are disabled, so no race.
        // The Mutex type REQUIRES the cs token,
        // so you cannot forget the critical section.
    });
}

fn main() -> ! {
    // Update from main loop
    critical_section::with(|cs| {
        *HALF_PERIOD.borrow_ref_mut(cs) = 500;
    });
    // The compiler ENFORCES that both the ISR
    // and main use critical sections.
}
```

### src/main.rs

```rust
//! Potentiometer-controlled servo with buzzer feedback on the Raspberry Pi Pico.
//!
//! GP0  (PWM0A): Servo signal (50 Hz, 0.5-2.5 ms pulse)
//! GP18 (GPIO):  Piezo buzzer (toggled by timer interrupt)
//! GP26 (ADC0):  Potentiometer wiper
//!
//! The potentiometer sets the servo angle (0-180 degrees).
//! The buzzer plays a tone proportional to the angle:
//!   0 degrees -> 200 Hz, 180 degrees -> 2000 Hz.
//! The buzzer frequency is generated by a timer alarm interrupt
//! that toggles the buzzer GPIO at the required half-period.

#![no_std]
#![no_main]

use core::cell::RefCell;
use critical_section::Mutex;
use panic_halt as _;
use defmt_rtt as _;

use rp_pico::entry;
use rp_pico::hal;
use rp_pico::hal::pac;
use rp_pico::hal::pac::interrupt;
use rp_pico::hal::Clock;

use embedded_hal::digital::{OutputPin, StatefulOutputPin};
use embedded_hal::pwm::SetDutyCycle;
use embedded_hal_0_2::adc::OneShot;

// ================================================================
// Shared state between main loop and TIMER_IRQ_0 interrupt handler
// ================================================================

/// The raw TIMER peripheral, moved into the ISR via Option.
static TIMER_PERIPH: Mutex<RefCell<Option<pac::TIMER>>> =
    Mutex::new(RefCell::new(None));

/// Buzzer half-period in microseconds. 0 means buzzer off.
/// Updated by main loop, read by ISR.
static BUZZER_HALF_PERIOD_US: Mutex<RefCell<u32>> =
    Mutex::new(RefCell::new(0));

/// Buzzer GPIO pin, moved into the ISR via Option.
/// Using the specific pin type for GP18 configured as push-pull output.
type BuzzerPin = hal::gpio::Pin<
    hal::gpio::bank0::Gpio18,
    hal::gpio::FunctionSio<hal::gpio::SioOutput>,
    hal::gpio::PullDown,
>;
static BUZZER_PIN: Mutex<RefCell<Option<BuzzerPin>>> =
    Mutex::new(RefCell::new(None));

// ================================================================
// Timer interrupt handler: toggles buzzer at the configured frequency
// ================================================================

#[interrupt]
fn TIMER_IRQ_0() {
    critical_section::with(|cs| {
        let timer_ref = TIMER_PERIPH.borrow_ref(cs);
        let half_period = *BUZZER_HALF_PERIOD_US.borrow_ref(cs);

        if let Some(ref timer) = *timer_ref {
            // Clear the alarm 0 interrupt flag
            timer.intr().write(|w| w.alarm_0().clear_bit_by_one());

            if half_period > 0 {
                // Toggle the buzzer pin
                let mut pin_ref = BUZZER_PIN.borrow_ref_mut(cs);
                if let Some(ref mut pin) = *pin_ref {
                    if pin.is_set_high().unwrap_or(false) {
                        let _ = pin.set_low();
                    } else {
                        let _ = pin.set_high();
                    }
                }
            }

            // Schedule the next alarm. An alarm fires only once, so it
            // must always be re-armed. While the buzzer is off, check
            // again every 10 ms so that a new half-period is picked up.
            let interval = if half_period > 0 { half_period } else { 10_000 };
            let now = timer.timerawl().read().bits();
            let next = now.wrapping_add(interval);
            timer.alarm0().write(|w| unsafe { w.bits(next) });
        }
    });
}

// ================================================================
// Helper functions
// ================================================================

/// Map a 12-bit ADC value (0-4095) to a servo angle (0-180).
fn adc_to_angle(adc_val: u16) -> u16 {
    ((adc_val as u32 * 180) / 4095) as u16
}

/// Map a servo angle (0-180) to a PWM compare value for the servo.
/// Servo expects 0.5 ms to 2.5 ms pulse in a 20 ms period.
/// With the divider set so that the counter runs at 1 MHz and wrap = 19999:
///   0 degrees   -> 500  (0.5 ms)
///   90 degrees  -> 1500 (1.5 ms)
///   180 degrees -> 2500 (2.5 ms)
fn angle_to_servo_duty(angle: u16) -> u16 {
    let angle = if angle > 180 { 180 } else { angle };
    500 + ((angle as u32 * 2000) / 180) as u16
}

/// Map a servo angle (0-180) to a buzzer frequency (200-2000 Hz).
/// Returns the half-period in microseconds for the timer interrupt.
/// Returns 0 if angle is 0 (buzzer off at minimum).
fn angle_to_buzzer_half_period(angle: u16) -> u32 {
    if angle == 0 {
        return 0; // buzzer off
    }
    // Frequency: 200 Hz at 0 degrees, 2000 Hz at 180 degrees
    let freq_hz = 200 + ((angle as u32 * 1800) / 180);
    // Half-period in microseconds: 1_000_000 / (2 * freq_hz)
    1_000_000 / (2 * freq_hz)
}

// ================================================================
// Entry point
// ================================================================

#[entry]
fn main() -> ! {
    defmt::info!("Booting rp2040-servo-buzzer");

    // ---- Peripheral setup ----
    let mut pac = pac::Peripherals::take().unwrap();
    let core = pac::CorePeripherals::take().unwrap();
    let mut watchdog = hal::Watchdog::new(pac.WATCHDOG);

    let clocks = hal::clocks::init_clocks_and_plls(
        rp_pico::XOSC_CRYSTAL_FREQ,
        pac.XOSC,
        pac.CLOCKS,
        pac.PLL_SYS,
        pac.PLL_USB,
        &mut pac.RESETS,
        &mut watchdog,
    )
    .ok()
    .unwrap();

    defmt::info!(
        "System clock: {} MHz",
        clocks.system_clock.freq().to_MHz()
    );

    // ---- GPIO setup ----
    let sio = hal::Sio::new(pac.SIO);
    let pins = rp_pico::Pins::new(
        pac.IO_BANK0,
        pac.PADS_BANK0,
        sio.gpio_bank0,
        &mut pac.RESETS,
    );

    // ---- PWM setup for servo (GP0, slice 0, channel A) ----
    let pwm_slices = hal::pwm::Slices::new(pac.PWM, &mut pac.RESETS);
    let mut pwm0 = pwm_slices.pwm0;

    // Configure for 50 Hz: 125 MHz / 125 = 1 MHz counter, wrap at 19999
    pwm0.set_div_int(125);
    pwm0.set_div_frac(0);
    pwm0.set_top(19999);
    pwm0.enable();

    // Assign GP0 to PWM0A
    let channel_a = &mut pwm0.channel_a;
    channel_a.output_to(pins.gpio0);

    // Start at center (90 degrees = 1500 us pulse)
    channel_a.set_duty_cycle(1500).unwrap();

    defmt::info!("Servo PWM configured: 50 Hz on GP0");

    // ---- Buzzer GPIO setup (GP18 as push-pull output) ----
    let buzzer_pin = pins.gpio18.into_push_pull_output();

    // Move the buzzer pin into the static for ISR access
    critical_section::with(|cs| {
        BUZZER_PIN.borrow_ref_mut(cs).replace(buzzer_pin);
    });

    // ---- ADC setup (GP26 = ADC0 for potentiometer) ----
    let mut adc = hal::Adc::new(pac.ADC, &mut pac.RESETS);
    let mut adc_pin = hal::adc::AdcPin::new(pins.gpio26).unwrap();

    defmt::info!("ADC configured on GP26");

    // ---- Timer alarm setup for buzzer interrupt ----
    // We need the raw TIMER peripheral for alarm interrupts.
    // The HAL Timer type does not expose alarm interrupts directly
    // in a way that works cleanly with the static Mutex pattern,
    // so we use the PAC directly for the alarm.

    // Note: pac.TIMER was already used by hal::Timer if we created one.
    // Instead, we access it through the Mutex after moving it there.

    // Enable alarm 0 interrupt in the TIMER peripheral
    // We need to configure this before moving the peripheral

    // Bring the TIMER peripheral out of reset first. hal::Timer::new()
    // normally does this, but here we use the PAC directly.
    pac.RESETS.reset().modify(|_, w| w.timer().clear_bit());
    while pac.RESETS.reset_done().read().timer().bit_is_clear() {}

    let timer = pac.TIMER;
    timer.inte().modify(|_, w| w.alarm_0().set_bit());

    // Set an initial alarm (will be reconfigured by the ISR)
    let initial_alarm = timer.timerawl().read().bits().wrapping_add(100_000);
    timer.alarm0().write(|w| unsafe { w.bits(initial_alarm) });

    // Move the TIMER peripheral into the static for ISR access
    critical_section::with(|cs| {
        TIMER_PERIPH.borrow_ref_mut(cs).replace(timer);
    });

    // Enable the TIMER_IRQ_0 interrupt in the NVIC
    unsafe {
        pac::NVIC::unmask(pac::Interrupt::TIMER_IRQ_0);
    }

    defmt::info!("Timer alarm 0 interrupt enabled for buzzer");

    // ---- Create a SysTick-based delay for the main loop ----
    let mut delay = cortex_m::delay::Delay::new(
        core.SYST,
        clocks.system_clock.freq().to_Hz(),
    );

    // ---- Main loop ----
    let mut last_angle: u16 = 255; // impossible value to force first update

    defmt::info!("Entering main loop. Turn the potentiometer.");

    loop {
        // Read the potentiometer (12-bit: 0 to 4095)
        let adc_value: u16 = adc.read(&mut adc_pin).unwrap();

        // Map to servo angle (0 to 180 degrees)
        let angle = adc_to_angle(adc_value);

        // Only update if the angle changed (reduces servo jitter)
        if angle != last_angle {
            // Update servo PWM duty cycle
            let duty = angle_to_servo_duty(angle);
            pwm0.channel_a.set_duty_cycle(duty).unwrap();

            // Update buzzer frequency via the shared Mutex
            let half_period = angle_to_buzzer_half_period(angle);
            critical_section::with(|cs| {
                *BUZZER_HALF_PERIOD_US.borrow_ref_mut(cs) = half_period;
            });

            defmt::info!(
                "ADC: {} | Angle: {} deg | Servo duty: {} | Buzzer half-period: {} us",
                adc_value,
                angle,
                duty,
                half_period
            );

            last_angle = angle;
        }

        // Small delay to avoid flooding the ADC and RTT
        delay.delay_ms(20);
    }
}
```

## Timer Architecture on the RP2040

<InArticleAd />

The RP2040 has one 64-bit timer that counts microseconds, with 4 alarm registers. An alarm interrupts when the lower 32 bits of the timer equal its value, and it fires once: the handler must set the next alarm itself, like a kitchen timer you wind again after each ring. An STM32 instead has several separate timers, each with a prescaler and an auto-reload register.

| Feature | RP2040 Timer | STM32 General-Purpose Timer |
|---------|-------------|---------------------------|
| Counter width | 64-bit (read as two 32-bit halves) | 16-bit or 32-bit |
| Clock source | 1 MHz (fixed from reference clock) | Configurable via prescaler |
| Alarm/compare channels | 4 (alarm 0 through 3) | 4 (per timer) |
| Auto-reload | No (alarms are one-shot, re-arm manually) | Yes (ARR register) |
| PWM generation | Not via timer (separate PWM peripheral) | Built into timer channels |

### Why We Use Both Timer and PWM

On the RP2040 the timer and the PWM hardware are separate. The servo uses PWM: no CPU time and no timing error. The buzzer uses a timer alarm interrupt that switches a GPIO pin. A second PWM slice at 50% duty, with a new wrap value for each pitch, would also make the tone with no CPU time; the interrupt is used here because its way of sharing data is needed in most real projects.

## Interrupt Safety Deep Dive

<InArticleAd />

### Why `unsafe` for NVIC::unmask?

```rust
unsafe {
    pac::NVIC::unmask(pac::Interrupt::TIMER_IRQ_0);
}
```

`unsafe` marks an operation the compiler cannot check, where you promise you have. The NVIC is the interrupt controller of the ARM core, and `unmask` switches one interrupt on. From then on the handler can run in the middle of any other code, and could break a critical section that relies on this interrupt being off. The compiler cannot see whether your shared data is ready, so it asks you to say so. The block is small on purpose: it shows a reviewer the one line to examine.

### The `Option` Pattern for Moving Peripherals into ISRs

A `static` must have its value when the program is built, but a peripheral exists only at run time, after `Peripherals::take()`. `Mutex<RefCell<Option<T>>>` joins the two:

1. The static starts as `None`.
2. In `main()`, after you configure the peripheral, you move it into the static with `.replace(peripheral)`.
3. In the ISR, you borrow the static and test for `Some(ref peripheral)`.

This is longer than the C code, which writes to the registers directly. In return, a handler that touches the peripheral outside a critical section, or before it is set up, does not compile.

### Atomic Operations as an Alternative

For one simple value such as the buzzer half-period (a single `u32`), `core::sync::atomic::AtomicU32` can replace `Mutex<RefCell<u32>>`. An atomic type is read or written in one step that cannot be interrupted, so interrupts stay on:

```rust
use core::sync::atomic::{AtomicU32, Ordering};

static BUZZER_HALF_PERIOD_ATOMIC: AtomicU32 = AtomicU32::new(0);

// In main loop:
BUZZER_HALF_PERIOD_ATOMIC.store(half_period, Ordering::Relaxed);

// In ISR:
let hp = BUZZER_HALF_PERIOD_ATOMIC.load(Ordering::Relaxed);
```

This costs less, but it works only for one value. For several values that must agree (a frequency and a duration), use the Mutex pattern.

:::tip[Instrument it]
The same timer measures signals. The time between two pulses of a Hall sensor gives the speed of a shaft in RPM. An ADC reading started by a timer samples a sensor at an exact rate, which vibration and current measurements need. With the timing done in hardware, a Pico can [report true rates and waveforms](/education/iot-systems/) to [siliconwit.io](https://siliconwit.io).
:::

## Production Notes

<InArticleAd />

<Card title="Production Considerations" icon="setting">

**Servo signal quality:** The counter runs in hardware, so the servo pulse has no timing error from the program. A new compare value is held in a buffer and takes effect at the start of the next period, so no pulse is cut short.

**ADC noise:** The ADC of the RP2040 is noisy, more so when USB is active. Average several readings and add a 100 nF capacitor between the ADC input and ground. For fast sampling, let DMA collect the readings (DMA is shown with the UART later in the course).

**Interrupt latency:** Interrupts are off while the closure of a critical section runs, so keep it short. Here the ISR switches one pin and sets one alarm, which takes a few microseconds. Where even that is too long, use atomics.

**Power management:** The SG90 draws a high current while it moves. On a battery, switch the servo supply off with a MOSFET on a GPIO pin when the servo is at rest.
</Card>
