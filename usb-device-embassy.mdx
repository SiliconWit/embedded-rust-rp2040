You plug in a USB device you made and the computer shows "device not recognized", with no other message. The usual cause in C is one wrong byte in a descriptor, the table in which a device tells the computer what it is, and you find that byte only with a protocol analyzer. The RP2040 has a USB controller on the chip, so it needs no USB-to-serial bridge chip, and it can appear as a serial port, a keyboard or both at once. In this lesson you use embassy-usb, which builds the descriptors for you from a few calls. You make a virtual serial port that sends sensor readings, a keyboard that types when you press a button, and then one device that is both. #USB #EmbassyRust #HID

## USB on the RP2040

<InArticleAd />


USB differs from UART in one way that explains everything else in this lesson: the two sides are not equal. The computer is the host and it starts every exchange. The Pico is a device and it only answers. A device that has data must wait until the host asks for it.

Four words follow from this:

- An endpoint is a numbered channel inside the device, with one direction. IN means from the device to the host, OUT means from the host to the device. The directions are always named from the side of the host.
- Endpoint 0 is the control endpoint. Every device has it, and the host uses it to ask questions.
- A descriptor is a block of bytes in which the device answers one of those questions: who made you, what are you, which endpoints do you have.
- A class is an agreed kind of device (serial port, keyboard, storage). The operating system already has a driver for each class, so the device needs no driver of its own.

The RP2040's controller works at USB 1.1 Full Speed (12 Mbit/s). It has 16 endpoint numbers (0 to 15, each usable in the IN and the OUT direction) and 4 kB of RAM for the endpoint buffers. The electrical part (the PHY) is on the chip, so the D+ and D- data lines go from the connector to the chip with only a few passive parts, which the Pico board already has.

When you plug the Pico into a host, this happens:

<Steps>
1. The host sees the device, because a pull-up resistor on the D+ line marks a Full Speed device.

2. The host resets the bus and starts enumeration: it reads the descriptors through endpoint 0 and gives the device an address.

3. From the descriptors, the host chooses the class drivers: a serial port driver for CDC ACM, the built-in input driver for HID.

4. The host selects a configuration (usually configuration 1). Now the other endpoints can carry data.
</Steps>

The `embassy-usb` crate does this for you. You describe the device with a builder (an object that collects the parts in a few calls and then produces the finished device). The library writes the descriptors, gives out the endpoint numbers, and answers the host.

### USB Descriptor Hierarchy

The descriptors of a device form a tree with four levels:

| Level | Descriptor | Purpose |
|-------|-----------|---------|
| 1 | Device Descriptor | Vendor ID, product ID, USB version, device class |
| 2 | Configuration Descriptor | Groups interfaces; specifies max power draw |
| 3 | Interface Descriptor | One function (HID, CDC, MSC, etc.) with its class codes |
| 4 | Endpoint Descriptor | Communication pipe: direction, transfer type, packet size, polling interval |

A composite device has several interfaces under one configuration. This device has three: two for CDC (one for commands, one for data) and one for HID. Bulk and Interrupt in the tree are transfer types: a bulk endpoint carries data of any amount when the bus has time, and an interrupt endpoint is asked by the host at a fixed interval.

```text
  Device Descriptor
  ├── VID: 0xC0DE, PID: 0xCAFE
  └── Configuration 1 (max 100 mA)
      ├── Interface 0: CDC ACM (Communication)
      │   └── Endpoint 1 IN (Interrupt, 8 bytes)
      ├── Interface 1: CDC ACM (Data)
      │   ├── Endpoint 2 IN  (Bulk, 64 bytes)
      │   └── Endpoint 1 OUT (Bulk, 64 bytes)
      └── Interface 2: HID Keyboard
          ├── Endpoint 3 IN  (Interrupt, 8 bytes)
          └── Endpoint 2 OUT (Interrupt, 8 bytes)
```

## USB CDC: Virtual Serial Port

<InArticleAd />


USB CDC ACM (Communication Device Class, Abstract Control Model) is the class for a serial port that has no UART behind it. On the host it appears as `/dev/ttyACM0` on Linux, a port such as `COM3` on Windows, or `/dev/cu.usbmodem*` on macOS, and a program opens it as it opens any serial port. The baud rate you choose in the terminal has no effect, because no UART exists. The data travels at USB speed.

The first program is CDC alone. It reads the potentiometer with the ADC and prints the value on the USB serial port every 500 ms.

### Circuit Connections (CDC Only)

| Pico Pin | Component | Function |
|----------|-----------|----------|
| GP26 (ADC0) | Potentiometer wiper | Analog input |
| 3V3 | Potentiometer one end | Reference voltage |
| GND | Potentiometer other end | Ground reference |

### CDC Firmware

```rust title="src/main.rs (CDC only)"
#![no_std]
#![no_main]

use defmt::*;
use defmt_rtt as _;
use panic_probe as _;

use embassy_executor::Spawner;
use embassy_rp::adc::{Adc, Channel, Config as AdcConfig, InterruptHandler as AdcIrq};
use embassy_rp::bind_interrupts;
use embassy_rp::gpio::Pull;
use embassy_rp::peripherals::USB;
use embassy_rp::usb::{Driver, InterruptHandler as UsbIrq};
use embassy_time::Timer;
use embassy_usb::class::cdc_acm::{CdcAcmClass, State};
use embassy_usb::UsbDevice;

use static_cell::StaticCell;

bind_interrupts!(struct Irqs {
    USBCTRL_IRQ => UsbIrq<USB>;
    ADC_IRQ_FIFO => AdcIrq;
});

#[embassy_executor::task]
async fn usb_task(mut usb: UsbDevice<'static, Driver<'static, USB>>) {
    usb.run().await;
}

#[embassy_executor::main]
async fn main(spawner: Spawner) {
    let p = embassy_rp::init(Default::default());

    // Create USB driver
    let driver = Driver::new(p.USB, Irqs);

    // Configure USB device descriptor
    let mut config = embassy_usb::Config::new(0xc0de, 0xcafe);
    config.manufacturer = Some("Pico Workshop");
    config.product = Some("Pico CDC Sensor");
    config.serial_number = Some("001");
    config.max_power = 100; // 100 mA
    config.max_packet_size_0 = 64;

    // Allocate buffers for the USB stack
    static CONFIG_DESC: StaticCell<[u8; 256]> = StaticCell::new();
    static BOS_DESC: StaticCell<[u8; 256]> = StaticCell::new();
    static CONTROL_BUF: StaticCell<[u8; 64]> = StaticCell::new();
    static CDC_STATE: StaticCell<State> = StaticCell::new();

    let config_desc = CONFIG_DESC.init([0; 256]);
    let bos_desc = BOS_DESC.init([0; 256]);
    let control_buf = CONTROL_BUF.init([0; 64]);
    let cdc_state = CDC_STATE.init(State::new());

    // Build the USB device
    let mut builder = embassy_usb::Builder::new(
        driver,
        config,
        config_desc,
        bos_desc,
        &mut [], // no msos descriptors
        control_buf,
    );

    // Create CDC ACM class
    let mut cdc = CdcAcmClass::new(&mut builder, cdc_state, 64);

    // Build and spawn the USB device task
    let usb = builder.build();
    spawner.spawn(usb_task(usb)).unwrap();

    // Set up ADC for potentiometer on GP26
    let mut adc = Adc::new(p.ADC, Irqs, AdcConfig::default());
    let mut pot_pin = Channel::new_pin(p.PIN_26, Pull::None);

    // Main loop: read ADC and write to USB serial
    let mut buf = [0u8; 64];
    loop {
        // Wait until the host has configured the device
        cdc.wait_connection().await;
        info!("CDC connected");

        loop {
            let adc_val = adc.read(&mut pot_pin).await.unwrap_or(0);
            let voltage_mv = (adc_val as u32 * 3300) / 4095;

            // Format the output string
            let msg = format_msg(&mut buf, adc_val, voltage_mv);

            // Write to USB CDC; break if disconnected
            if cdc.write_packet(msg).await.is_err() {
                info!("CDC disconnected");
                break;
            }

            Timer::after_millis(500).await;
        }
    }
}

fn format_msg(buf: &mut [u8; 64], raw: u16, mv: u32) -> &[u8] {
    // Manual formatting since we are in no_std
    let mut pos = 0;

    let prefix = b"ADC: ";
    buf[pos..pos + prefix.len()].copy_from_slice(prefix);
    pos += prefix.len();

    pos += write_u32(&mut buf[pos..], raw as u32);

    let mid = b" | ";
    buf[pos..pos + mid.len()].copy_from_slice(mid);
    pos += mid.len();

    pos += write_u32(&mut buf[pos..], mv);

    let suffix = b" mV\r\n";
    buf[pos..pos + suffix.len()].copy_from_slice(suffix);
    pos += suffix.len();

    &buf[..pos]
}

fn write_u32(buf: &mut [u8], val: u32) -> usize {
    if val == 0 {
        buf[0] = b'0';
        return 1;
    }
    let mut tmp = [0u8; 10];
    let mut n = val;
    let mut i = 0;
    while n > 0 {
        tmp[i] = b'0' + (n % 10) as u8;
        n /= 10;
        i += 1;
    }
    for j in 0..i {
        buf[j] = tmp[i - 1 - j];
    }
    i
}
```

**How it works:** `embassy_usb::Builder` makes the descriptor tree when the program starts. It needs memory to write into, so you give it buffers for the configuration descriptor, the BOS descriptor (Binary Object Store, a second descriptor that newer hosts ask for) and the control endpoint. The buffers are `static`, because the USB task uses them for the whole run. `CdcAcmClass::new()` adds the two CDC interfaces and their three endpoints, and the builder chooses the numbers.

The host can ask a question at any moment, so the USB stack needs a task of its own. `usb_task` answers the host during enumeration and afterwards. Your code and the USB task take turns at each `.await`:

- `cdc.wait_connection().await` waits until the host has configured the device.
- `cdc.write_packet(...).await` waits until the host has collected the packet.
- If the cable is unplugged or the bus is reset, `write_packet` returns an error, and the code goes back to waiting for a connection.

## USB HID: Keyboard

<InArticleAd />


USB HID (Human Interface Device) is the class for keyboards, mice, gamepads and other input devices. A HID device sends reports: small packets of fixed size that give its state now (which keys are down, how far the mouse moved). It also sends, once, a report descriptor that tells the host what each bit of a report means. This is why a HID device works on every operating system with no driver of its own.

A keyboard report says which keys are down at this moment. It does not say "a key was pressed". So one key press needs two reports: one with the key down, and one with no key down. Without the second report the host believes that the key is still held.

### HID Report Descriptor

This report descriptor defines a standard keyboard: 8 modifier keys (Ctrl, Shift, Alt, GUI, left and right) and room for 6 ordinary keys held together:

```rust
// Standard keyboard report descriptor
// Byte 0: modifier keys (Ctrl, Shift, Alt, GUI)
// Byte 1: reserved (padding)
// Bytes 2-7: up to 6 simultaneous key codes
const KEYBOARD_REPORT_DESC: &[u8] = &[
    0x05, 0x01,        // Usage Page (Generic Desktop)
    0x09, 0x06,        // Usage (Keyboard)
    0xA1, 0x01,        // Collection (Application)

    // Modifier keys (8 bits)
    0x05, 0x07,        //   Usage Page (Key Codes)
    0x19, 0xE0,        //   Usage Minimum (Left Control)
    0x29, 0xE7,        //   Usage Maximum (Right GUI)
    0x15, 0x00,        //   Logical Minimum (0)
    0x25, 0x01,        //   Logical Maximum (1)
    0x75, 0x01,        //   Report Size (1)
    0x95, 0x08,        //   Report Count (8)
    0x81, 0x02,        //   Input (Data, Variable, Absolute)

    // Reserved byte
    0x95, 0x01,        //   Report Count (1)
    0x75, 0x08,        //   Report Size (8)
    0x81, 0x01,        //   Input (Constant)

    // Key codes (6 bytes)
    0x95, 0x06,        //   Report Count (6)
    0x75, 0x08,        //   Report Size (8)
    0x15, 0x00,        //   Logical Minimum (0)
    0x25, 0x65,        //   Logical Maximum (101)
    0x05, 0x07,        //   Usage Page (Key Codes)
    0x19, 0x00,        //   Usage Minimum (0)
    0x29, 0x65,        //   Usage Maximum (101)
    0x81, 0x00,        //   Input (Data, Array)

    0xC0,              // End Collection
];
```

The descriptor is read in pairs: "Report Size" is the number of bits in one field, "Report Count" is the number of such fields, and "Input" closes the group. So the three groups are 8 fields of 1 bit, 1 field of 8 bits and 6 fields of 8 bits, which gives a report of 8 bytes:

| Byte | Content |
|------|---------|
| 0 | Modifier flags, one bit per key: Left Ctrl, Left Shift, Left Alt, Left GUI, then the same four on the right |
| 1 | Reserved, always 0 |
| 2 to 7 | Up to 6 key codes. 0x00 means "no key" in that place |

### Keyboard Report Structure

```rust
#[derive(Clone, Copy)]
#[repr(C, packed)]
struct KeyboardReport {
    modifier: u8,
    reserved: u8,
    keycodes: [u8; 6],
}

impl KeyboardReport {
    const fn empty() -> Self {
        Self {
            modifier: 0,
            reserved: 0,
            keycodes: [0; 6],
        }
    }

    fn with_key(keycode: u8) -> Self {
        Self {
            modifier: 0,
            reserved: 0,
            keycodes: [keycode, 0, 0, 0, 0, 0],
        }
    }

    fn as_bytes(&self) -> &[u8] {
        unsafe {
            core::slice::from_raw_parts(
                self as *const _ as *const u8,
                core::mem::size_of::<Self>(),
            )
        }
    }
}
```

### USB HID Key Codes

A keyboard does not send characters. It sends the number of a key, as the key is placed on a US keyboard, and the operating system chooses the character from its own layout setting. The same code 0x1C gives "y" on a computer set to a US layout and "z" on one set to a German layout. Common codes:

| Key | HID Code | Key | HID Code |
|-----|----------|-----|----------|
| A | 0x04 | 1 | 0x1E |
| B | 0x05 | 2 | 0x1F |
| C | 0x06 | Space | 0x2C |
| H | 0x0B | Enter | 0x28 |
| E | 0x08 | Period | 0x37 |
| L | 0x0F | Comma | 0x36 |
| O | 0x12 | Exclamation | Shift + 0x1E |

To type "h" you send a report with key code 0x0B. To type "H" you send the same key code and set the Left Shift bit (bit 1 of the modifier byte, value 0x02), as a person holds Shift.

## Composite Device: CDC + HID

<InArticleAd />


The complete project puts both classes into one USB device.

### Circuit Connections

| Pico Pin | Component | Function |
|----------|-----------|----------|
| GP26 (ADC0) | Potentiometer wiper | Analog input for CDC serial data |
| GP15 | Push button (one leg) | HID keyboard trigger |
| GND | Button other leg, pot end | Ground |
| 3V3 | Potentiometer end | Reference voltage |

The button connects GP15 to GND. The code turns on the internal pull-up resistor, so the pin reads high when the button is released and low when it is pressed. The 10K resistor of the parts list is not used.

```rust title="src/main.rs"
        buf[0] = b'0';
        return 1;
    }
    let mut tmp = [0u8; 10];
    let mut n = val;
    let mut i = 0;
    while n > 0 {
        tmp[i] = b'0' + (n % 10) as u8;
        n /= 10;
        i += 1;
    }
    for j in 0..i {
        buf[j] = tmp[i - 1 - j];
    }
    i
}

// ── HID Keyboard Task ─────────────────────────────────────────────

#[embassy_executor::task]
async fn hid_task(
    hid: HidReaderWriter<'static, Driver<'static, USB>, 1, 8>,
    mut button: Input<'static>,
) {
    let (reader, mut writer) = hid.split();

    // We only use the writer. The report descriptor defines no
    // output reports, so the reader is kept but never read.
    let _reader = reader;

    // The string to type when the button is pressed
    let message: &[u8] = b"Hello from Pico!";

    loop {
        // Wait for button press (falling edge: high to low)
        button.wait_for_falling_edge().await;
        info!("Button pressed, typing message");

        // Type each character
        for &ch in message {
            let keycode = ascii_to_hid(ch);
            let needs_shift = ch.is_ascii_uppercase()
                || matches!(ch, b'!' | b'@' | b'#' | b'$' | b'%'
                    | b'^' | b'&' | b'*' | b'(' | b')');

            // Key down
            let report = KeyboardReport {
                modifier: if needs_shift { 0x02 } else { 0x00 },
                reserved: 0,
                keycodes: [keycode, 0, 0, 0, 0, 0],
            };
            let _ = writer.write(report.as_bytes()).await;

            // Small delay between key down and key up
            Timer::after_millis(10).await;

            // Key up (empty report)
            let empty = KeyboardReport::empty();
            let _ = writer.write(empty.as_bytes()).await;

            // Delay between characters
            Timer::after_millis(30).await;
        }

        // Debounce: wait before accepting the next press
        Timer::after_millis(300).await;
    }
}

/// Convert an ASCII character to a USB HID keycode.
fn ascii_to_hid(ch: u8) -> u8 {
    match ch {
        b'a'..=b'z' => ch - b'a' + 0x04,
        b'A'..=b'Z' => ch - b'A' + 0x04,
        b'1'..=b'9' => ch - b'1' + 0x1E,
        b'0' => 0x27,
        b' ' => 0x2C,
        b'!' => 0x1E, // Shift + 1
        b'@' => 0x1F, // Shift + 2
        b'#' => 0x20, // Shift + 3
        b'.' => 0x37,
        b',' => 0x36,
        b'\n' => 0x28, // Enter
        b'-' => 0x2D,
        b'=' => 0x2E,
        b'[' => 0x2F,
        b']' => 0x30,
        b'\\' => 0x31,
        b';' => 0x33,
        b'\'' => 0x34,
        b'/' => 0x38,
        _ => 0x00, // No key
    }
}

// ── Main ───────────────────────────────────────────────────────────

#[embassy_executor::main]
async fn main(spawner: Spawner) {
    let p = embassy_rp::init(Default::default());

    // ── USB Device Configuration ───────────────────────────────────

    let driver = Driver::new(p.USB, Irqs);

    let mut config = embassy_usb::Config::new(0xc0de, 0xcafe);
    config.manufacturer = Some("Pico Workshop");
    config.product = Some("Pico CDC+Keyboard");
    config.serial_number = Some("RUST-001");
    config.max_power = 100;
    config.max_packet_size_0 = 64;
    // Composite device: class defined at interface level
    config.device_class = 0xEF;    // Miscellaneous
    config.device_sub_class = 0x02; // Common Class
    config.device_protocol = 0x01;  // Interface Association Descriptor

    // ── Static Buffers ─────────────────────────────────────────────

    static CONFIG_DESC: StaticCell<[u8; 256]> = StaticCell::new();
    static BOS_DESC: StaticCell<[u8; 256]> = StaticCell::new();
    static MSOS_DESC: StaticCell<[u8; 256]> = StaticCell::new();
    static CONTROL_BUF: StaticCell<[u8; 64]> = StaticCell::new();
    static CDC_STATE: StaticCell<CdcState> = StaticCell::new();
    static HID_STATE: StaticCell<HidState> = StaticCell::new();

    let config_desc = CONFIG_DESC.init([0; 256]);
    let bos_desc = BOS_DESC.init([0; 256]);
    let msos_desc = MSOS_DESC.init([0; 256]);
    let control_buf = CONTROL_BUF.init([0; 64]);
    let cdc_state = CDC_STATE.init(CdcState::new());
    let hid_state = HID_STATE.init(HidState::new());

    // ── Build USB Device ───────────────────────────────────────────

    let mut builder = embassy_usb::Builder::new(
        driver,
        config,
        config_desc,
        bos_desc,
        msos_desc,
        control_buf,
    );

    // Add CDC ACM class (virtual serial port)
    let cdc = CdcAcmClass::new(&mut builder, cdc_state, 64);

    // Add HID class (keyboard)
    let hid_config = embassy_usb::class::hid::Config {
        report_descriptor: KEYBOARD_REPORT_DESC,
        request_handler: None,
        poll_ms: 10,
        max_packet_size: 8,
    };
    let hid = HidReaderWriter::<_, 1, 8>::new(&mut builder, hid_state, hid_config);

    // Build the USB device
    let usb = builder.build();

    // ── Peripherals ────────────────────────────────────────────────

    // ADC for potentiometer
    let adc = Adc::new(p.ADC, Irqs, AdcConfig::default());
    let pot_pin = Channel::new_pin(p.PIN_26, Pull::None);

    // Button on GP15 with internal pull-up
    let button = Input::new(p.PIN_15, Pull::Up);

    // ── Spawn Tasks ────────────────────────────────────────────────

    spawner.spawn(usb_task(usb)).unwrap();
    spawner.spawn(cdc_task(cdc, adc, pot_pin)).unwrap();
    spawner.spawn(hid_task(hid, button)).unwrap();

    info!("USB composite device started: CDC + HID Keyboard");

    // Main task has nothing else to do; it can idle forever.
    // The executor will run the spawned tasks.
    loop {
        Timer::after_millis(1000).await;
    }
}
```

### How the Composite Device Works

**Three tasks:** `usb_task` answers the host. `cdc_task` reads the potentiometer and writes text to the serial port. `hid_task` waits for the button and sends keyboard reports. Only one of them runs at any moment, and each gives the processor back at every `.await`. Each task owns its own hardware (the ADC, the button pin), so no lock is needed.

**The host sets the pace:** `poll_ms: 10` asks the host to collect a keyboard report every 10 ms. `writer.write(...).await` finishes when the host has taken the report, not when the task wants. The drawing follows one character:

```text
 time (ms)  0    10   20   30   40   50   60
            │    │    │    │    │    │    │
 host asks  ?    ?    ?    ?    ?    ?    ?
 hid_task   █....█....█....█..............█
            a    b    c    d              e
```

- a: the button is pressed. The task writes "key down" and waits for the host.
- b: the host took the report. The task waits 10 ms.
- c: the task writes "key up" (the empty report) and waits for the host.
- d: the host took it. The task waits 30 ms.
- e: the task writes "key down" for the next character.

At every dot the other two tasks can run. While the task types, and for 300 ms after the text, it does not wait for the button, so a press in that time is ignored. This also covers contact bounce.

**The builder:** `CdcAcmClass::new()` adds two interfaces and three endpoints. `HidReaderWriter::new()` adds one interface with one interrupt IN and one interrupt OUT endpoint. The builder chooses every number.

**Composite class codes:** The device descriptor uses class 0xEF (Miscellaneous), subclass 0x02, protocol 0x01. This tells the host to look for Interface Association Descriptors (IADs), which mark the two CDC interfaces as one function. Without these codes some operating systems, Windows in particular, do not recognize the CDC part of a composite device.

## C vs Rust: USB Descriptor Construction

<InArticleAd />


In C with TinyUSB you write the descriptors as arrays of bytes. Every position, length and value must be correct, or the host rejects the device. A typical TinyUSB configuration descriptor for a composite CDC+HID device:

```c title="C with TinyUSB (error-prone)"
// Must manually calculate CONFIG_TOTAL_LEN
#define CONFIG_TOTAL_LEN (TUD_CONFIG_DESC_LEN + TUD_CDC_DESC_LEN + TUD_HID_DESC_LEN)

static const uint8_t desc_configuration[] = {
    TUD_CONFIG_DESCRIPTOR(1, 3, 0, CONFIG_TOTAL_LEN, 0x00, 100),
    TUD_CDC_DESCRIPTOR(0, 4, 0x81, 8, 0x02, 0x82, 64),
    TUD_HID_DESCRIPTOR(2, 5, HID_ITF_PROTOCOL_NONE,
                       sizeof(desc_hid_report), 0x83, 8, 10),
};
```

Common mistakes with this approach:
- Wrong `CONFIG_TOTAL_LEN` (forgot to update after adding an interface)
- Duplicate endpoint numbers (0x82 used twice)
- Wrong interface count (says 3 but only defines 2)
- Byte order errors in multi-byte fields
- Mismatched HID report descriptor length

With embassy-usb you do not write these numbers, so you cannot write them wrong:

```rust title="Rust with embassy-usb (type-safe)"
let mut builder = embassy_usb::Builder::new(driver, config, ...);

// Each call automatically:
//   - Allocates the next available interface numbers
//   - Allocates the next available endpoint numbers
//   - Computes the correct descriptor lengths
//   - Adds the Interface Association Descriptor for CDC
let cdc = CdcAcmClass::new(&mut builder, cdc_state, 64);
let hid = HidReaderWriter::new(&mut builder, hid_state, hid_config);

let usb = builder.build(); // Finalizes CONFIG_TOTAL_LEN automatically
```

The builder calculates the interface numbers, the endpoint numbers and the lengths. If you ask for more endpoints than the hardware has, the program stops with a clear panic message at startup. The host does not reject the device without a reason.

### Troubleshooting

| Symptom | Likely Cause | Fix |
|---------|-------------|-----|
| Device not recognized | Descriptor buffer too small | Increase CONFIG_DESC size from 256 to 512 |
| CDC port not visible | Missing IAD class codes | Verify device_class = 0xEF, sub_class = 0x02, protocol = 0x01 |
| Keyboard types wrong characters | Keycode mapping error | Check `ascii_to_hid()` against the USB HID Usage Tables |
| Button press types multiple times | Debounce too short | Increase the 300 ms debounce delay |
| ADC reads stuck at 0 | Wiring issue | Verify potentiometer wiper connects to GP26, ends to 3V3 and GND |
| Firmware panics on startup | Endpoint allocation failed | RP2040 supports 16 endpoint numbers in each direction; the composite device uses 7 endpoints, counting the two control endpoints (well within limits) |

## Production Notes

<InArticleAd />


**Vendor and product IDs:** The IDs 0xc0de:0xcafe of this lesson are for development only. A product needs a vendor ID from the USB Implementers Forum (USB-IF), or a product ID from a shared program such as pid.codes, which gives free product IDs under vendor ID 0x1209.

**Compliance testing:** A consumer USB device should pass the USB-IF compliance tests. Embassy-usb answers the required standard requests. If you add requests of your own, test them with the USB Command Verifier (USB CV) tool.

**String descriptors:** Give real manufacturer, product and serial number strings. The serial number should differ for every unit. You can make it from the unique ID of the flash chip (through `embassy_rp::flash`).

**Power:** Declare the true current in `max_power`. USB 2.0 allows up to 500 mA per port, but some hubs and laptops give less.

**Suspend and resume:** A USB device must use little power when the host suspends the bus, for example when the computer sleeps. To lower the power use of your own code, implement the `suspended()` callback of the `embassy_usb::Handler` trait and register it with `builder.handler()`.

## Summary

<InArticleAd />


On USB the host starts every exchange and the device answers through numbered endpoints. A device tells the host what it is with descriptors, and a class such as CDC or HID lets it use a driver that the operating system already has. You built a composite device: a CDC serial port that sends potentiometer readings and a HID keyboard that types on a button press. The embassy-usb builder wrote the descriptors. A keyboard report gives the keys that are down now, as key numbers and not as characters, so each key press is two reports. Three tasks share the processor, and each owns its hardware, so the program has no locks.
